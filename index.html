1. Arquitecturas Web

¿Qué es una arquitectura web?

La arquitectura web es el diseño conceptual y la estructura lógica que define cómo se comunican y organizan los diferentes componentes de un sistema web (como el cliente, el servidor, las bases de datos y las interfaces de programación o APIs). Su propósito es asegurar que la aplicación sea eficiente, segura, escalable y ofrezca una buena experiencia al usuario, gestionando cómo viaja la información a través de la red.

Principales tipos de arquitecturas web

  • Monolítica: Todo el código del sistema (interfaz de usuario, lógica de negocio y acceso a datos) está unificado en una sola base de código y se despliega como una única unidad.
  • Cliente-Servidor (N-Capas): Divide la aplicación en capas lógicas. La más común es la de 3 capas: Presentación (Frontend), Lógica de negocio (Backend) y Datos (Base de datos).
  • Microservicios: La aplicación se divide en pequeños servicios independientes que se comunican entre sí a través de APIs. Cada servicio tiene su propia lógica y base de datos.
  • Serverless (Sin servidor): El desarrollador se enfoca solo en escribir el código en forma de funciones. El proveedor de la nube (como AWS o Google Cloud) gestiona dinámicamente la asignación de recursos y los servidores.

Arquitecturas más utilizadas actualmente

En la actualidad, las arquitecturas basadas en Microservicios y Cliente-Servidor (separando Frontend en SPA y Backend en APIs REST/GraphQL) son las más dominantes. Las empresas tecnológicas modernas prefieren los microservicios por su capacidad de escalar partes específicas de una aplicación, aunque las monolíticas siguen siendo muy comunes para proyectos pequeños o startups que buscan un desarrollo rápido inicial.

Comparación de Arquitecturas

Característica Monolítica Microservicios Serverless
Estructura Unidad única e indivisible. Múltiples servicios pequeños e independientes. Funciones ejecutadas bajo demanda (eventos).
Ventajas Fácil de desarrollar, probar y desplegar al inicio. Alta resiliencia; si falla un servicio, el resto sigue funcionando. Independencia tecnológica. No hay que gestionar servidores. Pago exclusivo por tiempo de ejecución.
Desventajas Si una parte falla, puede caer todo el sistema. Difícil de actualizar. Difícil de orquestar y monitorear. Latencia de red entre servicios. Dependencia del proveedor (Vendor lock-in). Problemas de latencia en "arranques en frío" (cold starts).
Escalabilidad Baja/Costosa (se debe duplicar toda la aplicación). Muy Alta (se escala solo el servicio que lo requiere). Automática e infinita (gestionada por la nube).
Complejidad Baja en etapas tempranas, altísima a medida que crece. Alta desde el inicio (requiere DevOps avanzado). Media (requiere cambio de paradigma de programación).
Costos Costos fijos por servidor, haya tráfico o no. Altos costos de infraestructura y mantenimiento. Muy bajos con poco tráfico, variables según consumo.
Casos de uso Startups, blogs, aplicaciones internas simples. Netflix, Amazon, aplicaciones empresariales complejas. Procesamiento de datos en tiempo real, bots, tareas en segundo plano.

2. HTTP y HTTPS

¿Qué es HTTP?

HTTP (Hypertext Transfer Protocol - Protocolo de Transferencia de Hipertexto) es el protocolo fundamental de la World Wide Web. Define las reglas de cómo se formatean y transmiten los mensajes entre el navegador web (cliente) y el servidor web. Sigue un modelo de petición-respuesta: el cliente envía una petición HTTP para acceder a un recurso (como una página HTML o una imagen) y el servidor devuelve una respuesta HTTP con ese recurso o un mensaje de error. Por defecto, HTTP envía la información en texto plano, lo que significa que cualquiera que intercepte la comunicación puede leer los datos.

¿Qué es HTTPS?

HTTPS (Hypertext Transfer Protocol Secure) es la versión segura de HTTP. Funciona exactamente igual en cuanto a la comunicación cliente-servidor, pero añade una capa de seguridad criptográfica (TLS/SSL). Esta capa cifra los datos antes de que viajen por la red, garantizando que, si la información es interceptada (como contraseñas o tarjetas de crédito), los atacantes solo verán caracteres ilegibles y no podrán descifrarlos sin la llave criptográfica correcta.

Comparación: HTTP vs HTTPS

Característica HTTP HTTPS
Funcionamiento Transmite datos en texto plano. Transmite datos cifrados mediante algoritmos criptográficos.
Seguridad Nula. Vulnerable a ataques Man-in-the-Middle (MitM). Alta. Garantiza confidencialidad, integridad y autenticación.
Puerto habitual Puerto 80 Puerto 443
Cifrado No posee cifrado. Usa protocolos SSL o TLS.
Escenarios de uso Pruebas locales o sitios estáticos muy antiguos sin datos sensibles (cada vez menos aceptado). Comercio electrónico, banca, redes sociales y hoy en día, el estándar obligatorio para cualquier sitio web.

3. SSL y TLS

¿Qué son SSL y TLS?

SSL (Secure Sockets Layer) y TLS (Transport Layer Security) son protocolos criptográficos diseñados para proporcionar comunicaciones seguras a través de una red informática. Su función principal es establecer un "túnel" cifrado entre dos sistemas (como tu navegador y el servidor de tu banco) para asegurar que los datos no puedan ser leídos ni modificados por terceros.

Diferencias y su relación con HTTPS

La relación con HTTPS es directa: HTTPS es simplemente el protocolo HTTP ejecutándose sobre una capa de seguridad SSL o TLS. En cuanto a sus diferencias, TLS es en realidad el sucesor directo de SSL. Aunque a menudo se usan indistintamente en el lenguaje cotidiano (se sigue hablando de "Certificados SSL"), técnicamente SSL es la tecnología original de los años 90, mientras que TLS es la versión moderna, mejorada y más segura.

¿Por qué TLS es el estándar y SSL es obsoleto?

El protocolo SSL (en todas sus versiones: 1.0, 2.0 y 3.0) ha sido declarado obsoleto y deprecado (oficialmente en 2015 por la IETF) debido a graves vulnerabilidades de seguridad descubiertas en su diseño, como el famoso ataque POODLE, que permitía a los hackers descifrar conexiones seguras.

TLS es el estándar vigente (actualmente en sus versiones 1.2 y 1.3) porque utiliza algoritmos de cifrado mucho más robustos, procesos de negociación de claves (handshakes) más rápidos y seguros, y elimina funciones criptográficas débiles del pasado. Hoy en día, ningún navegador web moderno permite conexiones con el antiguo protocolo SSL.
